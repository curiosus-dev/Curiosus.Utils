Requires `net9.0` or `net10.0`. Coming from `Curiosity.*` 1.x? Start with the [overview](../index.md).

`Curiosus.DAL` 3.0 moves `DbOptions` to `Microsoft.Extensions.Options`. A larger rework of the data access packages,
which replaces `Curiosus.DAL` with `Curiosus.DAL.EF`, is planned in
[#68](https://github.com/curiosus-dev/Curiosus.Utils/issues/68).

## Breaking changes

- [Options](#options) ([#44](https://github.com/curiosus-dev/Curiosus.Utils/issues/44))

## Options

`DbOptions` was checked with `AssertValid()` of the `Curiosus.Configuration` options model, so a missing connection
string failed on the first resolve instead of at start. Now `DbOptions` is a plain options class: `ConnectionString` has
`[Required]` (null, empty and whitespace fail, as before), and the app registers it with `ValidateOnStart`.

Removed from `DbOptions`: `IValidatableOptions`, `ILoggableOptions` and `Validate(string? prefix)`. The package no longer
depends on `Curiosus.Configuration`: add a reference to it if your app used it through this package.

Before:

```csharp
var dbOptions = configuration.GetSection("Db").Get<DbOptions>()!;
dbOptions.AssertValid("Db");
services.AddSingleton(dbOptions);

public class AppDataContextFactory(DbOptions options) : ICuriosusDataContextFactory { /* options.ConnectionString */ }
```

After:

```csharp
services.AddOptions<DbOptions>()
    .BindConfiguration("Db")
    .ValidateDataAnnotations()
    .ValidateOnStart();

public class AppDataContextFactory(IOptions<DbOptions> options) : ICuriosusDataContextFactory
{
    /* options.Value.ConnectionString */
}
```

`services.AddCuriosusOptions<DbOptions>("Db")` of `Curiosus.Configuration` 2.1 does the same in one call. If many
classes take `DbOptions` directly, keep them as they are and register the value:
`services.AddSingleton(sp => sp.GetRequiredService<IOptions<DbOptions>>().Value)`.

### Subclasses of DbOptions

A subclass keeps working: `ValidateDataAnnotations()` on the subclass checks the attributes of the inherited properties
too, so `ConnectionString` stays required. The rules of an overridden `Validate` move to attributes on the subclass
(single-property rules) or to an `IValidateOptions<T>` of the subclass (rules across properties).

Before:

```csharp
public class AppDbOptions : DbOptions
{
    public int CommandTimeoutSec { get; set; } = 30;
    public bool UseReadOnlyReplica { get; set; }

    public override IReadOnlyCollection<ConfigurationValidationError> Validate(string? prefix = null)
    {
        var errors = new ConfigurationValidationErrorCollection(prefix);
        errors.AddErrors(base.Validate(prefix));
        errors.AddErrorIf(CommandTimeoutSec <= 0, nameof(CommandTimeoutSec), "must be positive");
        errors.AddErrorIf(UseReadOnlyReplica && String.IsNullOrWhiteSpace(ReadOnlyConnectionString),
            nameof(ReadOnlyConnectionString), "is required when UseReadOnlyReplica is true");
        return errors;
    }
}

var dbOptions = configuration.GetSection("Db").Get<AppDbOptions>()!;
dbOptions.AssertValid("Db");
services.AddSingleton(dbOptions);
```

After:

```csharp
public class AppDbOptions : DbOptions
{
    [Range(1, 3600)]
    public int CommandTimeoutSec { get; set; } = 30;

    public bool UseReadOnlyReplica { get; set; }
}

public class AppDbOptionsValidator : IValidateOptions<AppDbOptions>
{
    public ValidateOptionsResult Validate(string? name, AppDbOptions options)
    {
        var builder = new ValidateOptionsResultBuilder();
        if (options.UseReadOnlyReplica && String.IsNullOrWhiteSpace(options.ReadOnlyConnectionString))
        {
            builder.AddError("is required when UseReadOnlyReplica is true", "Db:ReadOnlyConnectionString");
        }

        return builder.Build();
    }
}

services.AddOptions<AppDbOptions>()
    .BindConfiguration("Db")
    .ValidateDataAnnotations()      // [Required] of DbOptions.ConnectionString and [Range] of the subclass
    .ValidateOnStart();
services.AddSingleton<IValidateOptions<AppDbOptions>, AppDbOptionsValidator>();
```

`base.Validate(prefix)` has no counterpart to call: the base rules are attributes, and `ValidateDataAnnotations()` of the
subclass applies them. `DbOptions` has no `IValidateOptions` of its own, so the subclass validator has nothing to chain.
Options are registered by their own type: inject `IOptions<AppDbOptions>`, not `IOptions<DbOptions>`.

Checklist:

- [ ] Replace `Get<DbOptions>()` + `AssertValid()` + `AddSingleton(options)` with
  `AddOptions<DbOptions>().BindConfiguration("Db").ValidateDataAnnotations().ValidateOnStart()` (or your subclass).
- [ ] Inject `IOptions<DbOptions>` (or `IOptions<AppDbOptions>`) instead of the options instance.
- [ ] Move the rules of an overridden `Validate` to attributes or an `IValidateOptions<T>` of the subclass; drop the
  `base.Validate` call.
- [ ] Reference `Curiosus.Configuration` yourself if the app uses it and got it only through `Curiosus.DAL`.
- [ ] Start the app with a missing `Db:ConnectionString`: it must fail with `OptionsValidationException` at start.
