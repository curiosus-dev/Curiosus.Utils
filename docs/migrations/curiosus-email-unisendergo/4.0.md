Requires `net9.0` or `net10.0`. Coming from `Curiosity.*` 1.x? Start with the [overview](../index.md).

`Curiosus.EMail.UnisenderGo` 4.0 moves the options to `Microsoft.Extensions.Options`. This page grows with each change
of the release ([#44](https://github.com/curiosus-dev/Curiosus.Utils/issues/44)).

## Breaking changes

- [Options](#options) ([#44](https://github.com/curiosus-dev/Curiosus.Utils/issues/44))

## Options

The options moved from the `Curiosus.Configuration` model (`IValidatableOptions`, `AssertValid()`) to
`Microsoft.Extensions.Options`: the sender takes `IOptions<UnisenderGoEmailOptions>`, and the options are validated
when the host starts instead of on registration. An invalid `UnisenderGo` section makes `IHost.StartAsync` throw an
`OptionsValidationException` that lists every failed option. The package no longer references `Curiosus.Configuration`.

Before:

```csharp
var unisenderOptions = configuration.GetSection("UnisenderGo").Get<UnisenderGoEmailOptions>()!;
services.AddUnisenderGoEmailSender(unisenderOptions);
```

After:

```csharp
services.AddUnisenderGoEmailSender()
    .BindConfiguration("UnisenderGo");

// or in code, together with or instead of the binding
services.AddUnisenderGoEmailSender(o => o.ApiKey = secrets.UnisenderGoApiKey)
    .BindConfiguration("UnisenderGo");
```

`useAsDefaultSender: false` still registers only `IUnisenderGoEmailSender`. The configuration keys and the named
`HttpClient` didn't change.

| Before | After |
|---|---|
| `AddUnisenderGoEmailSender(UnisenderGoEmailOptions options, bool useAsDefaultSender = true)` returning `IServiceCollection` | `AddUnisenderGoEmailSender(Action<UnisenderGoEmailOptions>? configure = null, bool useAsDefaultSender = true)` returning `OptionsBuilder<UnisenderGoEmailOptions>` |
| `new UnisenderGoEmailSender(logger, UnisenderGoEmailOptions, httpClientFactory)` | `new UnisenderGoEmailSender(logger, IOptions<UnisenderGoEmailOptions>, httpClientFactory)`, for example with `Options.Create(options)` |
| `options.Validate(prefix)`, `options.AssertValid()` | data annotations on `UnisenderGoEmailOptions` (`ApiKey`, `EmailFrom`, `FromName` required, `Region` a defined value), run by `ValidateOnStart` |

A subclass of `UnisenderGoEmailOptions` that overrode `Validate(prefix)`: keep it for your own code, but the sender
reads `IOptions<UnisenderGoEmailOptions>`, so bind the section for `UnisenderGoEmailOptions` too. Move the extra rules to
data annotations or to an `IValidateOptions<UnisenderGoEmailOptions>` registered with
`services.TryAddEnumerable(ServiceDescriptor.Singleton<IValidateOptions<UnisenderGoEmailOptions>, MyRules>())`.

Checklist:

- [ ] Replace `AddUnisenderGoEmailSender(options)` with `AddUnisenderGoEmailSender().BindConfiguration("UnisenderGo")`
  (your section name).
- [ ] Remove `AssertValid()` calls on `UnisenderGoEmailOptions`.
- [ ] Wrap options in `Options.Create(...)` where you create `UnisenderGoEmailSender` yourself (tests).
- [ ] Start the app once with the production configuration: a missing or invalid value now fails the start.
