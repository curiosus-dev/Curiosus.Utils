Requires `net9.0` or `net10.0`. Coming from `Curiosity.*` 1.x? Start with the [overview](../index.md).

`Curiosus.Hosting.Web` 4.0 keeps only `CuriosusWebHost.CreateBuilder(args)`: web apps move from the bootstrapper and a
`Startup` class to a top-level `Program.cs` on `WebApplication`, with the defaults of
[Curiosus.Hosting 4.0](../curiosus-hosting/4.0.md) ([#42](https://github.com/curiosus-dev/Curiosus.Utils/issues/42)).

## Breaking changes

- [Startup → Program.cs](#startup--programcs) ([#42](https://github.com/curiosus-dev/Curiosus.Utils/issues/42))

## Startup → Program.cs

The bootstrapper configured Kestrel by hand from a second copy of the configuration, overwrote the environment with
`ASPNETCORE_ENVIRONMENT` (`null` when unset), always added thread pool tuning, and `ConfigureCuriosusMvc` built a
service provider inside `ConfigureServices` (ASP0000). `WebApplication` does all of it natively.

Removed: `CuriosusWebAppBootstrapper`, `ICuriosusWebAppConfiguration` / `CuriosusWebAppConfiguration` and its validator,
`KestrelOptions` / `EndpointOptions` / `EndpointCertificate`, `StartupHelper.ConfigureCuriosusMvc`, the `ModelBinder`
resources and `WebSiteResourceKeys`. The package no longer references `Curiosus.Tools.Web`, `MailKit`, `NLog.MailKit`
(both still come with `Curiosus.Hosting`), Razor runtime compilation and `System.ComponentModel.Annotations`.

Before:

```csharp
public class Startup
{
    public void ConfigureServices(IServiceCollection services)
    {
        var configuration = services.BuildServiceProvider().GetRequiredService<AppConfiguration>();
        services.ConfigureCuriosusMvc(configuration);
    }

    public void Configure(IApplicationBuilder app)
    {
        app.UseRouting();
        app.UseEndpoints(endpoints => endpoints.MapControllers());
    }
}

return await new CuriosusWebAppBootstrapper<CuriosusCLIArguments, AppConfiguration, Startup>().RunAsync(args);
```

After:

```csharp
var builder = CuriosusWebHost.CreateBuilder(args).AddCuriosusDefaults();
builder.AddCuriosusNLog(configureNLogExtensions: extensions => extensions.RegisterNLogWeb());
builder.Services.AddCuriosusOptions<SiteOptions>("Site");
builder.Services.AddControllersWithViews();

var app = builder.Build();
app.MapControllers();

return await CuriosusApp.RunAsync(app);
```

| Before | After |
|---|---|
| `Urls` | unchanged: `WebApplication` reads the `urls` key (also `ASPNETCORE_URLS`, `--urls`) |
| `Kestrel` section / `EndpointOptions` / `EndpointCertificate` | the native `Kestrel` section of the same shape, with reload and a startup error on a bad certificate |
| `UseIISIntegration` | part of the `WebApplication` defaults |
| `ThreadPool` | removed; call `AddThreadPoolTuning` of Curiosus.Hosting if needed (to be removed in [#45](https://github.com/curiosus-dev/Curiosus.Utils/issues/45)) |
| `SensitiveDataFieldNames` | `services.AddSensitiveDataProtector(fieldNames)` of Curiosus.Tools |
| `ConfigureCuriosusMvc` | `AddControllersWithViews()` / `AddRazorPages()`; localized model binding messages return in [#63](https://github.com/curiosus-dev/Curiosus.Utils/issues/63) |
| `IWebAppConfigurationWithPublicDomain` | still in Curiosus.Tools.Web; register your implementation yourself |
| `UseNLog()` / `RegisterNLogWeb()` in NLog.config | `AddCuriosusNLog(configureNLogExtensions: e => e.RegisterNLogWeb())` |
| non-generic `ILogger` named `main` | `ILogger<T>` |

Checklist:

- [ ] Move `Startup.ConfigureServices` / `Configure` into `Program.cs` on `CuriosusWebHost.CreateBuilder(args)`.
- [ ] Remove `UseIISIntegration`, `ThreadPool` and `SensitiveDataFieldNames` from `config.yml` or move them as above;
  keep `Urls` / `Kestrel`.
- [ ] Reference `Curiosus.Tools.Web` directly if the app uses it.
- [ ] Follow the [Curiosus.Hosting 4.0 notes](../curiosus-hosting/4.0.md) for configuration, initializers and logging.
