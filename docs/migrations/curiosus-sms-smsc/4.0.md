Requires `net9.0` or `net10.0`. Coming from `Curiosity.*` 1.x? Start with the [overview](../index.md).

4.0 registers `SmscOptions` with `Microsoft.Extensions.Options`: `AddSmscSmsSender` binds them from the `Smsc`
configuration section and validates them when the host starts, like the options of ASP.NET Core and other libraries.

## Breaking changes

- [Options](#options) ([#44](https://github.com/curiosus-dev/Curiosus.Utils/issues/44))

## Options

`SmscOptions` implemented the validation model of `Curiosus.Configuration` (`IValidatableOptions`, `AssertValid()`),
which is going away. Now the rules are data annotations (`[Required]` on `SmscLogin` and `SmscPassword`), checked by
`ValidateOnStart`: invalid configuration stops the host with `OptionsValidationException` naming the option, instead of
an exception from `AddSmscSmsSender`. A login or password of only whitespace is rejected too.

Before:

```csharp
var smscOptions = configuration.GetSection("Smsc").Get<SmscOptions>()!;
services.AddSmscSmsSender(smscOptions);
```

After:

```csharp
services.AddSmscSmsSender();   // binds the "Smsc" section (SmscOptions.SectionName)

// your configuration has another section: pass it, the files stay as they are
services.AddSmscSmsSender("Sms:Smsc");

// values set in code are applied after the section and override it; without a section they are enough
services.AddSmscSmsSender(configure: options =>
{
    options.SmscLogin = "my-login";
    options.SmscPassword = "my-password";
});
```

`useAsDefaultSender` stays, after the section and `configure`: `services.AddSmscSmsSender(useAsDefaultSender: false)`.
Only the first call of `AddSmscSmsSender` binds its section and registers the validation; later calls add their
`configure` only.

`AddSmscSmsSender` reads `IConfiguration` from the service provider, which every host registers. A bare
`ServiceCollection` (in tests, for example) needs one: `services.AddSingleton<IConfiguration>(configuration)`.

Code that creates the sender itself passes `IOptions<SmscOptions>`:

```csharp
var sender = new SmscSender(logger, Options.Create(smscOptions), httpClientFactory);
```

`Options.Create` doesn't validate: the sender no longer checks the options in its constructor.

A subclass of `SmscOptions` keeps working as a plain class: drop its `Validate(prefix)` override and move the rules to
attributes or an `IValidateOptions<SmscOptions>` registered next to `AddSmscSmsSender`:

```csharp
services.AddSmscSmsSender();
services.AddSingleton<IValidateOptions<SmscOptions>, MySmscOptionsValidator>();
```

The package no longer references `Curiosus.Configuration` directly; it still comes in through `Curiosus.SMS`.

Checklist:

- [ ] Replace `GetSection(...).Get<SmscOptions>()` and `AddSmscSmsSender(options)` with `AddSmscSmsSender()`, passing
  your section name if it isn't `Smsc`, or with `AddSmscSmsSender(configure: o => ...)`.
- [ ] Move named arguments: `useAsDefaultSender` now comes after `configSectionPath` and `configure`.
- [ ] Remove `AssertValid()` calls and `IValidatableOptions`/`ILoggableOptions` from your code around `SmscOptions`.
- [ ] Wrap options passed to `new SmscSender(...)` in `Options.Create(...)`.
- [ ] Start the app once with an empty password and check that it stops with an `OptionsValidationException`.
