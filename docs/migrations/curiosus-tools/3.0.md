## Clock: IDateTimeService → TimeProvider

.NET 8 added `System.TimeProvider`, the standard clock abstraction. `Task.Delay`, `PeriodicTimer`,
`CancellationTokenSource`, Polly v8 and `Microsoft.Extensions.Http.Resilience` accept it, so one clock reaches timers,
delays and resilience pipelines too, and tests get `FakeTimeProvider` instead of hand-written fakes.
`IDateTimeService`, `LocalDateTimeService` and `AddLocalDateTimeService` are removed, with no adapter and no
replacement registration method: the host registers the clock.

Before:

```csharp
services.AddLocalDateTimeService();

public class InvoiceService(IDateTimeService dateTimeService)
{
    public bool IsOverdue(Invoice invoice) => invoice.DueDateUtc < dateTimeService.GetCurrentTimeUtc();
}
```

After:

```csharp
services.AddSingleton(TimeProvider.System);   // the local clock, see "Which clock" below

public class InvoiceService(TimeProvider timeProvider)
{
    public bool IsOverdue(Invoice invoice) => invoice.DueDateUtc < timeProvider.GetUtcNow().UtcDateTime;
}
```

### Which clock

- **Local clock** (what `LocalDateTimeService` was): register `TimeProvider.System`. It is a singleton the BCL provides,
  there is nothing to configure. `AddCuriosusDefaults` of `Curiosus.Hosting` 4.0 will register it for you
  ([#41](https://github.com/curiosus-dev/Curiosus.Utils/issues/41)); until then add the line above to the host.
- **Database clock** (what `DbSyncDateTimeService` was): call `AddCuriosusDbSyncTimeProvider()`. It replaces the
  local `TimeProvider` registration whatever the order, so every class that takes `TimeProvider` gets the database
  clock, see [Curiosus.DateTime.DbSync 3.0](../curiosus-datetime-dbsync/3.0.md). Code that must keep the local clock
  in such an app (rare) uses `TimeProvider.System` directly.
- **Local time zone** rather than UTC: `timeProvider.GetLocalNow()`; the zone is `timeProvider.LocalTimeZone`
  (`TimeZoneInfo.Local` for `TimeProvider.System`).

`GetUtcNow()` returns a `DateTimeOffset`; `.UtcDateTime` gives the `DateTime` with `Kind = Utc` that
`GetCurrentTimeUtc()` returned. Drop `.UtcDateTime` where the code can work with `DateTimeOffset`.

Replace the calls with a regex: `(\w+)\.GetCurrentTimeUtc\(\)` → `$1.GetUtcNow().UtcDateTime`.

App interfaces that extend `IDateTimeService`: keep the app members on your own interface and inject `TimeProvider`
next to it. A clock synchronized with the database is `DbSyncTimeProvider`, see
[Curiosus.DateTime.DbSync 3.0](../curiosus-datetime-dbsync/3.0.md); it is released together with this version, since
`Curiosus.DateTime.DbSync` 2.x implements `IDateTimeService`.

Tests:

```csharp
// before
var dateTimeService = new Mock<IDateTimeService>();
dateTimeService.Setup(x => x.GetCurrentTimeUtc()).Returns(new System.DateTime(2026, 1, 1, 0, 0, 0, DateTimeKind.Utc));

// after (Microsoft.Extensions.TimeProvider.Testing)
var timeProvider = new FakeTimeProvider(new DateTimeOffset(2026, 1, 1, 0, 0, 0, TimeSpan.Zero));
timeProvider.Advance(TimeSpan.FromMinutes(5));
```

Checklist:

- [ ] `IDateTimeService` in constructors and fields → `TimeProvider`.
- [ ] `GetCurrentTimeUtc()` → `GetUtcNow().UtcDateTime` (regex above); check places where `DateTime` vs
  `DateTimeOffset` matters.
- [ ] `AddLocalDateTimeService()` → `services.AddSingleton(TimeProvider.System)` (or `AddCuriosusDefaults` once on
  `Curiosus.Hosting` 4.0).
- [ ] App interfaces extending `IDateTimeService` → own interface plus `TimeProvider`.
- [ ] `Curiosus.DateTime.DbSync` → 3.0 in the same step.
- [ ] `Mock<IDateTimeService>` and hand-written fakes → `FakeTimeProvider`.

## Performance logging: PerformanceManager → PerformanceMeasurer

`PerformanceManager` was static: `Measure` threw until Hosting had initialized it, and a measurer returned to the pool
twice could stop someone else's measurement. `PerformanceMeasurer` is a DI singleton and `Measure` returns a scope that
logs once. The log line stays the same: logger `performance`, template `{MeasurerName} -> {MeasurerSpentTime} ms`, whole
milliseconds, so NLog rules and dashboards keep working.

Before:

```csharp
using (PerformanceManager.Measure("Import"))
{
    // ...
}

using (var measurer = PerformanceManager.Measure("Import"))
{
    var id = LoadId();
    measurer.ReplaceName("Import {0}", id);
}
```

After:

```csharp
services.AddCuriosusPerformanceMeasurer();   // AddCuriosusDefaults of Curiosus.Hosting 4.0 will do it

public class Importer(PerformanceMeasurer performance)
{
    public void Import(int id)
    {
        using var _ = performance.Measure($"Import {id}");
        // ...
    }

    public void ImportNext()
    {
        using var scope = performance.Measure("Import");
        var id = LoadId();
        scope.ReplaceName($"Import {id}");
    }
}
```

For new code prefer metrics and traces: a `Histogram<double>` from `System.Diagnostics.Metrics` and an
`ActivitySource` reach OpenTelemetry (and centralized collection) without parsing log lines.

Checklist:

- [ ] `PerformanceManager.Measure(...)` → inject `PerformanceMeasurer`, `using var _ = performance.Measure(...)`.
- [ ] `Measure("... {0}", args)` and `ReplaceName("... {0}", args)` → string interpolation (`ReplaceName($"... {id}")`).
- [ ] Register `AddCuriosusPerformanceMeasurer()` unless the host does (Curiosus.Hosting registers it).

## Stuck code detection is removed

`StuckCodeManager` logged code sections that ran longer than a timeout to the `stuckcode` logger. Nothing used it, and
it needed a static logger, a static timer and initialization by Hosting, so it is removed rather than redesigned.

To catch code that hangs, give it a deadline (`CancellationTokenSource.CancelAfter`, `WaitAsync(timeout)`) or measure
it with an `Activity` / a duration histogram and alert on the duration in the monitoring system.

Checklist:

- [ ] Remove `StuckCodeManager.Initialize/Enter/Shutdown` calls and NLog rules for the `stuckcode` logger.

## Options

`TempFileOptions`, `HttpRequestParamsCalculatorOptions` and `CultureOptions` moved from the own options model of
`Curiosus.Configuration` (`IValidatableOptions`, `AssertValid`, `ILoggableOptions`) to `Microsoft.Extensions.Options`:
the rules are data annotations checked when the host starts, so an invalid section stops the app with an
`OptionsValidationException` that names every wrong option, and services read the options from `IOptions<T>`.

| Options | Rules |
|---|---|
| `TempFileOptions` | `TempPath` required; `CleaningFrequencyHours` and `FileTtlHours` at least 1 |
| `HttpRequestParamsCalculatorOptions` | `DataRateMBps` and `TimeoutMultiplier` greater than 0 (0 was accepted before) |
| `CultureOptions` | `DefaultCulture` required |

Before:

```csharp
var tempFileOptions = configuration.GetSection("TempFiles").Get<TempFileOptions>() ?? new TempFileOptions();
services.AddTempFileServices(tempFileOptions);

var calculatorOptions = configuration.GetSection("HttpRequestParams").Get<HttpRequestParamsCalculatorOptions>()!;
services.AddHttpRequestTimesCalculator(calculatorOptions);

var factory = new TempFileStreamFactory(new TempFileOptions { TempPath = "/tmp/app" });
```

After:

```csharp
services.AddTempFileServices();                  // binds the "TempFiles" section
services.AddHttpRequestTimesCalculator();        // binds the "HttpRequestParams" section

// another section, values in code on top of the bound ones
services.AddTempFileServices("App:TempFiles", o => o.TempPath = "/tmp/app");

// tests and code without DI
var factory = new TempFileStreamFactory(Options.Create(new TempFileOptions { TempPath = "/tmp/app" }));
```

- `AddTempFileServices`, `AddTempDirCleaner` of `Curiosus.Hosting` 4.0 and `AddSharpZipArchiver` of
  `Curiosus.Archiver.SharpZip` 3.0 register the same `TempFileOptions` (`AddTempFileOptions` registers them alone). Only the first of these calls binds
  its section and registers the validation, so an error is reported once; later calls only add their `configure` and
  their section path is ignored. The same holds for a second `AddHttpRequestTimesCalculator` call.
- The default sections are the `SectionName` constants: `TempFileOptions.SectionName` (`TempFiles`),
  `HttpRequestParamsCalculatorOptions.SectionName` (`HttpRequestParams`), `CultureOptions.SectionName` (`Culture`).
  A missing section leaves the defaults.
- Services that took `TempFileOptions` or `HttpRequestParamsCalculatorOptions` in the constructor
  (`TempFileStreamFactory`, `TempFilesInitService`, `HttpRequestParamsCalculator`) take `IOptions<T>`; inject
  `IOptions<TempFileOptions>` in your own classes too, since the options are no longer registered as a singleton
  instance.
- `ApplicationHelper.SetDefaultCulture(options)` keeps its signature and throws `ArgumentException` for an empty
  culture. Apps on `AddCuriosusDefaults` of `Curiosus.Hosting` 4.0 don't call it: the host applies `Culture:DefaultCulture`.
  To validate a bound `CultureOptions` on start:
  `services.AddOptions<CultureOptions>().BindConfiguration(CultureOptions.SectionName).ValidateDataAnnotations().ValidateOnStart()`.
- Subclasses of these options still compile, but the services read the base class (`IOptions<TempFileOptions>`): keep
  the registration above for them and bind the same section to the subclass with
  `services.AddOptions<TSubclass>().BindConfiguration("TempFiles")` for the app's own properties. A `Validate(prefix)`
  override becomes data annotations on the subclass or an `IValidateOptions<TSubclass>` registered with
  `services.TryAddEnumerable(ServiceDescriptor.Singleton<IValidateOptions<TSubclass>, TSubclassValidator>())`, plus
  `.ValidateDataAnnotations().ValidateOnStart()` on the subclass builder.
- The options are no longer `ILoggableOptions`: log the configuration with `LogConfigurationOnStart` of
  `Curiosus.Configuration` (secrets masked) instead of printing options objects.

Checklist:

- [ ] `AddTempFileServices(options)` → `AddTempFileServices()` (or `AddTempFileServices("Your:Section")`).
- [ ] `AddHttpRequestTimesCalculator(options)` → `AddHttpRequestTimesCalculator()` (or with your section path).
- [ ] Remove `options.AssertValid()` calls on these options.
- [ ] `TempFileOptions` / `HttpRequestParamsCalculatorOptions` in constructors → `IOptions<T>`;
  `new TempFileStreamFactory(options)` → `new TempFileStreamFactory(Options.Create(options))`.
- [ ] Check that `DataRateMBps` and `TimeoutMultiplier` are greater than 0 in the configuration.
- [ ] `Validate(prefix)` overrides in subclasses → data annotations or `IValidateOptions<T>`.
