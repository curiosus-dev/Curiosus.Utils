Requires `net9.0` or `net10.0`. Coming from `Curiosity.*` 1.x? Start with the [overview](../index.md).

`Curiosus.EMail.SMTP` 3.0 makes TLS protect the SMTP connection and moves the options to
`Microsoft.Extensions.Options`. This page grows with each change of the release
([#44](https://github.com/curiosus-dev/Curiosus.Utils/issues/44), [#85](https://github.com/curiosus-dev/Curiosus.Utils/issues/85),
[#86](https://github.com/curiosus-dev/Curiosus.Utils/issues/86)).

## Breaking changes

- [TLS is required and server certificates are validated](#tls-is-required-and-server-certificates-are-validated)
  ([#86](https://github.com/curiosus-dev/Curiosus.Utils/issues/86))
- [Options](#options) ([#44](https://github.com/curiosus-dev/Curiosus.Utils/issues/44))

## TLS is required and server certificates are validated

The sender accepted any server certificate (self-signed, expired, for another host, revoked) and used
`SecureSocketOptions.Auto`, which falls back to plain text when the server doesn't advertise STARTTLS. Anyone on the
network path could present their own certificate, or strip STARTTLS from the server's answer, and read the SMTP login,
the password and every message. Now the connection fails instead.

| Option | Before | Now |
|---|---|---|
| server certificate | any certificate accepted, revocation not checked | chain, host name and revocation checked by MailKit |
| port 465 | implicit TLS (`Auto`) | `SslOnConnect` |
| other ports | STARTTLS if the server offers it, otherwise **plain text** (`Auto`) | `StartTls`: fails if the server doesn't offer STARTTLS |
| `Security` | — | `StartTls`, `SslOnConnect` or `None` (local relay only); `Auto` and `StartTlsWhenAvailable` fail validation |
| `AllowInvalidServerCertificate` | — | accepts any certificate, meant for development relays; the sender logs a warning whenever it is set |

Before upgrading, check the relay from the app host:

```bash
openssl s_client -starttls smtp -connect smtp.example.com:587 -servername smtp.example.com
```

It must show STARTTLS, a certificate chain that verifies (`Verify return code: 0 (ok)`) and the relay's host name in the
certificate. For port 465 drop `-starttls smtp`.

After upgrading:

- `SslHandshakeException` (the error of the send response mentions the certificate) → fix the relay's certificate or
  trust its CA on the host. Don't fix it with `AllowInvalidServerCertificate`.
- An error that the server doesn't support STARTTLS (MailKit throws `NotSupportedException`) → enable STARTTLS on the relay. Set `Security: None` only
  for a relay on the same host or network that has no TLS at all (smtp4dev, a local Postfix).
- A development relay with a self-signed certificate:

```yaml
Smtp:
  SmtpServer: localhost
  SmtpPort: 1025
  AllowInvalidServerCertificate: true   # development relays; logs a warning
```

`SmtpEMailOptions` has the new members `Security` and `AllowInvalidServerCertificate`; `ISmtpEMailOptions` is gone, see
[Options](#options).

Checklist:

- [ ] Check every relay with `openssl s_client` before upgrading.
- [ ] Remove `Auto`/`StartTlsWhenAvailable` if you set `Security` already; set `None` only for a local relay.
- [ ] Keep `AllowInvalidServerCertificate` out of production configuration.
- [ ] **Rotate the SMTP passwords** used by earlier versions: they were sent over connections without certificate
  validation.

## Options

The options moved from the `Curiosus.Configuration` model (`IValidatableOptions`, `AssertValid()`) to
`Microsoft.Extensions.Options`: the sender takes `IOptions<SmtpEMailOptions>`, and the options are validated when the
host starts instead of on registration. An invalid `Smtp` section makes `IHost.StartAsync` throw an
`OptionsValidationException` that lists every failed option. The package no longer references `Curiosus.Configuration`.

Before:

```csharp
var smtpOptions = configuration.GetSection("Smtp").Get<SmtpEMailOptions>()!;
services.AddSmtpEMailSender(smtpOptions);
```

After:

```csharp
services.AddSmtpEMailSender();   // binds the "Smtp" section (SmtpEMailOptions.SectionName)

// another section
services.AddSmtpEMailSender("Mail:Smtp");

// values set in code, applied after the binding (works without a section too)
services.AddSmtpEMailSender(configure: o => o.SmtpPassword = secrets.SmtpPassword);
```

`useAsDefaultSender: false` still registers only `ISmtpEMailSender`. The configuration keys didn't change.

| Before | After |
|---|---|
| `AddSmtpEMailSender(ISmtpEMailOptions options, bool useAsDefaultSender = true)` returning `IServiceCollection` | `AddSmtpEMailSender(string configSectionPath = "Smtp", Action<SmtpEMailOptions>? configure = null, bool useAsDefaultSender = true)` binding the section and returning `OptionsBuilder<SmtpEMailOptions>` |
| `ISmtpEMailOptions` | `SmtpEMailOptions` |
| `new SmtpEMailSender(ISmtpEMailOptions, ILogger<SmtpEMailSender>)` | `new SmtpEMailSender(IOptions<SmtpEMailOptions>, ILogger<SmtpEMailSender>)`, for example with `Options.Create(options)` |
| `options.Validate(prefix)`, `options.AssertValid()` | data annotations on `SmtpEMailOptions` and `SmtpEMailOptionsValidator : IValidateOptions<SmtpEMailOptions>`, run by `ValidateOnStart` |
| `SmtpEMailOptionsValidator.Validate(this ISmtpEMailOptions, string? prefix)` | `new SmtpEMailOptionsValidator().Validate(name, options)` returning `ValidateOptionsResult` |
| `SmtpPort` up to `int.MaxValue` | `SmtpPort` from 1 to 65535 |

Your own options class:

- It implemented `ISmtpEMailOptions`: derive it from `SmtpEMailOptions` or drop it and use `SmtpEMailOptions`.
- It derived from `SmtpEMailOptions` and overrode `Validate(prefix)`: keep the subclass for your own code, but the
  sender reads `IOptions<SmtpEMailOptions>`, which `AddSmtpEMailSender` binds from the section. Move the extra rules to
  data annotations or to an `IValidateOptions<SmtpEMailOptions>` registered with
  `services.TryAddEnumerable(ServiceDescriptor.Singleton<IValidateOptions<SmtpEMailOptions>, MyRules>())`.

Checklist:

- [ ] Replace `AddSmtpEMailSender(options)` with `AddSmtpEMailSender()`, or `AddSmtpEMailSender("YourSection")` when the section
  has another name.
- [ ] Replace `ISmtpEMailOptions` with `SmtpEMailOptions`; remove `AssertValid()` calls on it.
- [ ] Wrap options in `Options.Create(...)` where you create `SmtpEMailSender` yourself (tests).
- [ ] Start the app once with the production configuration: a missing or invalid value now fails the start.
