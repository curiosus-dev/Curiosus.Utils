Requires `net9.0` or `net10.0`. Coming from `Curiosity.*` 1.x? Start with the [overview](../index.md).

`Curiosus.RabbitMQ` 4.0 gives an app one RabbitMQ connection and a publisher with publisher confirms. This page grows
with each change of the release ([#109](https://github.com/curiosus-dev/Curiosus.Utils/issues/109),
[#75](https://github.com/curiosus-dev/Curiosus.Utils/issues/75)); the RPC client changes with #75 in a later
pre-release.

## Breaking changes

- [Options and registration](#options-and-registration)
  ([#109](https://github.com/curiosus-dev/Curiosus.Utils/issues/109), [#44](https://github.com/curiosus-dev/Curiosus.Utils/issues/44))
- [RabbitMQ.Client 7.2.1](#rabbitmqclient-721) ([#109](https://github.com/curiosus-dev/Curiosus.Utils/issues/109))

Not breaking, but worth the move: [hand-written publishers](#hand-written-publishers) can be replaced with
`IRabbitPublisher`.

## Options and registration

`RabbitMQOptions` were built in code and checked with `AssertValid()`. Now they are bound from configuration and
validated when the host starts, like the options of the other Curiosus packages: invalid options stop the app before
it serves anything. One URI replaces the host, port and credentials, so a TLS connection (`amqps://`) and a virtual
host are configured the same way.

Before:

```yaml
RabbitMQ:
  HostName: rabbit.example.com
  Port: 5672
  UserName: app
  Password: secret
  ExchangeName: ""
  ClientName: billing-api
```

```csharp
services.AddRabbitMQRPC(configuration.RabbitMQ); // validated with AssertValid()

var client = await rpcClientFactory.CreateClientAsync("balance_requests", cancellationToken: cancellationToken);
```

After:

```yaml
RabbitMQ:
  ConnectionUri: amqp://app:secret@rabbit.example.com:5672/
  ClientName: billing-api
```

```csharp
services.AddCuriosusRabbitMQ(); // section "RabbitMQ" (RabbitMQOptions.SectionName); validated when the host starts

// or another section, and options set in code after binding
services.AddCuriosusRabbitMQ("Messaging:Rabbit", options => options.ClientName = "billing-api");

// it returns OptionsBuilder<RabbitMQOptions> for more rules
services.AddCuriosusRabbitMQ().Validate(options => options.PublishTimeout <= TimeSpan.FromMinutes(1), "Too long");

var client = await rpcClientFactory.CreateClientAsync(
    "balance_requests",
    requestExchange: "", // ExchangeName, if it was not empty
    cancellationToken: cancellationToken);
```

| Before | After |
|---|---|
| `HostName`, `Port`, `UserName`, `Password` | `ConnectionUri`: `amqp://user:password@host:port/vhost`, `amqps://` for TLS |
| `ExchangeName` | `requestExchange` argument of `RabbitMqRpcClientFactory.CreateClientAsync`, `""` by default |
| `ClientName`, default `BWKR_{machine name}` | `ClientName`, default the machine name; letters, digits, `.`, `_`, `-`, up to 64 characters |
| `services.AddRabbitMQRPC(options)`, returns `IServiceCollection` | `services.AddCuriosusRabbitMQ()`, returns `OptionsBuilder<RabbitMQOptions>`: section `RabbitMQ`; a section path and a `configure` action are optional |
| `new RabbitMqRpcClientFactory(loggerFactory, options)` | `new RabbitMqRpcClientFactory(loggerFactory, Options.Create(options))` |
| `options.AssertValid()`, `options.Validate()` | validation when the host starts (`RabbitMQOptionsValidator`) |
| — | `PublishTimeout` (30 s), `PublisherChannelCount` (4) of `IRabbitPublisher` |

The URI carries the password: keep it in user secrets or environment variables (`RabbitMQ__ConnectionUri`), not in a
committed file. Escape reserved characters of the user name and the password: `:` as `%3A`, `@` as `%40`, `/` as
`%2F`. The path is the virtual host: `/` or nothing selects the default one, `/prod` selects `prod`. For `amqps` the
server certificate must be valid for the host of the URI.

The RPC client names its response queues `{requestQueue}_responses_{ClientName}`. If you didn't set `ClientName`,
its default changed from `BWKR_{machine name}` to the machine name, and so did the queue names, the connection name
and the correlation ids. Set `ClientName: BWKR_<machine name>` to keep them, or delete the old response queues after
the upgrade.

Checklist:

- [ ] Replace `HostName`, `Port`, `UserName` and `Password` with `ConnectionUri`, kept in secrets.
- [ ] Move a non-empty `ExchangeName` to the `requestExchange` argument of `CreateClientAsync`.
- [ ] Set `ClientName` if you rely on the names of the RPC response queues; check it matches the pattern.
- [ ] Replace `AddRabbitMQRPC(options)` with `AddCuriosusRabbitMQ()` (move options built in code to its `configure`
  argument) and remove `AssertValid()` calls of the options. It returns the options builder: split
  `IServiceCollection` calls chained after it into separate statements.

## RabbitMQ.Client 7.2.1

The package needs `RabbitMQ.Client` 7.2.1 or later: in 7.0.0 a publish cancelled while waiting for its channel lets two
publishes send on that channel at once, and a returned message has no reply code. If the app references
`RabbitMQ.Client` itself, raise it to 7.2.1; 7.x is source compatible.

Checklist:

- [ ] Raise a direct `RabbitMQ.Client` reference to 7.2.1 or later.

## Hand-written publishers

Publishers written on top of `RabbitMQ.Client` usually open their own connection, run a reconnect loop on top of
auto-recovery, buffer messages in memory and report a message as sent without a publisher confirm, so a message can be
lost without an error. `IRabbitPublisher` publishes on the shared connection and completes only when the broker
confirmed the message; otherwise it throws `RabbitPublishException` within `PublishTimeout`.

Before:

```csharp
public class OrdersPublisher : BackgroundService
{
    private IConnection? _connection;
    private IChannel? _channel;
    private readonly SemaphoreSlim _lock = new(1, 1);

    // CreateConnectionAsync, a reconnect loop on ConnectionShutdownAsync, a queue of pending messages, ...

    public async Task PublishAsync(OrderPaid message, CancellationToken cancellationToken)
    {
        var body = JsonSerializer.SerializeToUtf8Bytes(message);
        await _lock.WaitAsync(cancellationToken);
        try
        {
            // no publisher confirm: completes when the message is written to the socket
            await _channel!.BasicPublishAsync("orders", "paid", false, new BasicProperties(), body, cancellationToken);
        }
        finally
        {
            _lock.Release();
        }
    }
}
```

After:

```csharp
// Program.cs
builder.Services.AddCuriosusRabbitMQ();

// declare the exchanges you publish to once at startup, for example in a hosted service
var connection = await connectionProvider.GetConnectionAsync(cancellationToken);
await using (var channel = await connection.CreateChannelAsync(cancellationToken: cancellationToken))
{
    await channel.ExchangeDeclareAsync("orders", ExchangeType.Direct, durable: true, cancellationToken: cancellationToken);
}

// anywhere: IRabbitPublisher is a thread-safe singleton
try
{
    await publisher.PublishAsync("orders", "paid", new OrderPaid(orderId, amount), cancellationToken: cancellationToken);
}
catch (RabbitPublishException e) when (e.Reason is RabbitPublishFailure.Timeout or RabbitPublishFailure.ConnectionLost)
{
    // not confirmed: retry later (consumers must be idempotent) or report the failure
}
```

What changes for the app:

- The message is JSON of `RabbitMQJson.DefaultOptions` with `content-type: application/json`, a `message-id` (a GUID v7
  unless you set `RabbitPublishProperties.MessageId`), a timestamp and `delivery-mode: 2` (persistent). Register your
  own `IRabbitMQMessageSerializer` for another format.
- Messages are not buffered: while the broker is unreachable, `PublishAsync` waits up to `PublishTimeout` and then
  throws with `Timeout`. Keep an outbox in your database if a message must survive that.
- After `ChannelClosed`, `ConnectionLost` or `Timeout` the message may have reached the broker. Publishing it again can
  deliver it twice: make consumers idempotent, for example by the `message-id`.
- A message no queue is bound for is confirmed and dropped by the broker; set `Mandatory = true` to get `Returned`.
- The exchange must exist: a publish to a missing one fails with `ChannelClosed` and reply code 404, together with the
  other publishes in flight on that channel.
- The broker shows one connection named `ClientName` with up to `PublisherChannelCount` channels, instead of one
  connection per publisher.

Checklist:

- [ ] Declare the exchanges (and queues) you publish to at startup.
- [ ] Replace the connection, the reconnect loop, the lock and the buffer of each publisher with `IRabbitPublisher`.
- [ ] Handle `RabbitPublishException`: retry or report, don't drop it silently.
- [ ] Make the consumers of these messages idempotent.
- [ ] Check that consumers read the JSON format of `RabbitMQJson.DefaultOptions` (property names as in the C# type).
