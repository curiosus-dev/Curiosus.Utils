Requires `net9.0` or `net10.0`, like 2.0. Coming from `Curiosity.*` 1.x? Start with the [overview](../index.md).

No code has to change: 2.1 changes what the startup configuration dump and validation errors look like. Apps get it
through `Curiosus.Hosting` and `Curiosus.Hosting.Web` too, whose bootstrappers print the configuration at startup.

## Changes

- [Secrets are masked in the printed configuration](#secrets-are-masked-in-the-printed-configuration)
  ([#39](https://github.com/curiosus-dev/Curiosus.Utils/issues/39))
- [Validation errors are in the exception message](#validation-errors-are-in-the-exception-message)
  ([#15](https://github.com/curiosus-dev/Curiosus.Utils/issues/15))

## Secrets are masked in the printed configuration

Earlier versions printed every option value in clear text, so passwords, API keys, tokens and connection string
passwords reached every log target: files, mail and chat targets, log storage. `ConfigurationPrinter` now masks them.

What changes in the output:

- Properties and dictionary keys whose name contains `password`, `pwd`, `passphrase`, `secret`, `token`, `credential`,
  `apikey`, `privatekey` (not `privatekeypath`), `signature`, `salt` or ends with `key` or `keys` print `***`.
  A collection under such a name prints `***` as a whole.
- A value that carries a secret itself prints `***`, whatever its name: a URI with user info
  (`amqp://user:pass@host`), a URL with `?token=`, `?sig=`, `?key=`, `?code=` and similar parameters, a connection string
  pair such as `Password=`, `Pwd=`, `AccountKey=` or `SharedAccessKey=` under any key name (`Server=x;Password=y`,
  `host:6379,password=y`), a Slack, Discord, Teams or Telegram bot webhook URL.
- Connection strings (names containing `connectionstring`) print only well-known non-secret keys: host, server, port,
  database, user, timeouts, SSL, pooling. Every other value prints `***`, and the keys are printed in lower case:

  ```text
  Before: ConnectionString: Host=db;Database=app;Username=app;Password=s3cr3t
  After:  ConnectionString: host=db;database=app;username=app;password=***
  ```

  A value that can't be parsed as a connection string, or contains a URI (`amqp://user:pass@host`), prints `***`.
- Dictionaries print as `{key=value, ...}` instead of `[[key, value], ...]`.
- Indexer properties are skipped, and an `ILoggableOptions` array element without properties no longer fails the
  startup.

Name matching can be overridden per property:

```csharp
public class AppOptions : ILoggableOptions
{
    [Secret]
    public string Endpoint { get; set; } = ""; // URL with credentials: always masked

    [NotSecret]
    public string ReCaptchaClientKey { get; set; } = ""; // public site key: printed as is
}
```

Checklist:

- [ ] Rotate the credentials that earlier versions logged: passwords, API keys, tokens, connection string passwords
  of every option the app printed at startup. Updating doesn't remove them from existing logs.
- [ ] Look at the startup dump of the app once: a secret whose name matches none of the patterns (a URL with
  credentials, a `Signature`) still prints. Mark it `[Secret]`.
- [ ] Mark `[NotSecret]` the values you need to see that are masked only because of their name (a public site key).
- [ ] Update log parsers or alerts that read the dump: masked values, lower-case connection string keys, the new
  dictionary format.

## Validation errors are in the exception message

`ConfigurationValidationException` dropped its message, so a failed start logged "Exception of type
'Curiosus.Configuration.ConfigurationValidationException' was thrown." without the invalid fields. `Message` now lists
them, the way `AssertValid` builds it:

```text
Option Smtp are invalid. Errors:
Smtp:Host: can't be empty
Smtp:Port: must be positive
```

Without a prefix the first line is `Options are invalid. Errors:` instead of `Option  are invalid. Errors:`.

Checklist:

- [ ] Code or alerts that match the old message text: match `ConfigurationValidationException` or its `Errors` instead.
