Requires `net9.0` or `net10.0`. Coming from `Curiosity.*` 1.x? Start with the [overview](../index.md).

`Curiosus.EMail.Mailgun` is removed: 3.0.0 is its last version, and all its versions are deprecated on NuGet
([#106](https://github.com/curiosus-dev/Curiosus.Utils/issues/106)).

## Breaking changes

- [The package is removed](#the-package-is-removed) ([#106](https://github.com/curiosus-dev/Curiosus.Utils/issues/106))

## The package is removed

No app used the package, and keeping it in step with the next majors of the e-mail packages (new message model, aligned
error codes, side-by-side registration) could only be tested against a paid Mailgun account. Mailgun accepts SMTP, which
[Curiosus.EMail.SMTP](../../packages/email/curiosus-email-smtp.md) covers with required TLS and certificate validation.

Three ways to move on, from the simplest:

1. **Mailgun over SMTP** with `Curiosus.EMail.SMTP`: the same Mailgun account and domain, no code beyond the registration.
2. **Another provider:** [Curiosus.EMail.UnisenderGo](../../packages/email/curiosus-email-unisendergo.md) sends through
   the Unisender Go HTTP API.
3. **Your own `IEMailSender`** on the Mailgun HTTP API, if you need its features (tags, templates, scheduled delivery):
   one `POST https://api.mailgun.net/v3/<domain>/messages` (`api.eu.mailgun.net` for the EU region) with basic
   authentication `api:<API key>` and a form body (`from`, `to`, `subject`, `text` or `html`), about 50 lines. The
   [3.0.0 source](https://github.com/curiosus-dev/Curiosus.Utils/tree/Curiosus.EMail.Mailgun.v3.0.0/src/Email/Curiosus.EMail.Mailgun)
   is a starting point.

Before:

```yaml
Mailgun:
  MailgunRegion: US
  MailgunUser: api
  MailgunApiKey: <secret>
  MailgunDomain: mg.example.com
  EmailFrom: noreply@mg.example.com
  ReplyTo: support@example.com
```

```csharp
using Curiosus.EMail.Mailgun;

var mailgunOptions = builder.Configuration.GetSection("Mailgun").Get<MailgunEmailOptions>()!;
builder.Services.AddMailgunEmailSender(mailgunOptions);
```

After, Mailgun over SMTP. Create an SMTP credential in the Mailgun control panel (Sending → Domain settings → SMTP
credentials): its login looks like `postmaster@mg.example.com`, the API key doesn't work as an SMTP password.

```yaml
Smtp:
  SmtpServer: smtp.mailgun.org     # smtp.eu.mailgun.org for the EU region
  SmtpPort: 587
  Security: StartTls
  SmtpLogin: postmaster@mg.example.com
  SmtpPassword: <secret>           # the SMTP credential's password
  EMailFrom: noreply@mg.example.com
  SenderName: Example
  ReplyTo: support@example.com
```

```csharp
using Curiosus.EMail.Smtp;

builder.Services.AddSmtpEMailSender().BindConfiguration("Smtp");   // validated when the host starts
```

Code that sends through `IEMailSender` stays as it is. Code that uses `IMailgunEmailSender` or
`MailgunEmailExtraParams` moves to `IEMailSender` and `SmtpEMailExtraParams` (sender address, name and reply-to per
message). Per-message Mailgun domains or API keys have no SMTP counterpart: register one sender per domain, or write
your own `IEMailSender`.

`Security` is an option of `Curiosus.EMail.SMTP` 3.0, see its [migration page](../curiosus-email-smtp/3.0.md); older
versions use STARTTLS on port 587 when the server offers it, which Mailgun does.

Checklist:

- [ ] Remove the `Curiosus.EMail.Mailgun` package reference.
- [ ] Create a Mailgun SMTP credential for the sending domain and keep its password with your other secrets.
- [ ] Register `AddSmtpEMailSender` (or `AddUnisenderGoEmailSender`) instead of `AddMailgunEmailSender` and move the
  options section.
- [ ] Replace `IMailgunEmailSender` and `MailgunEmailExtraParams` in your code.
- [ ] Send a test message and check that Mailgun logs it for the domain.
- [ ] Revoke the Mailgun API key if nothing else uses it.
