## The server host key is verified

The SFTP client accepted any host key: SSH.NET trusts every key when nobody handles `HostKeyReceived`. Anyone who could
redirect the traffic (DNS, ARP, a rogue network, a compromised hop) could answer with their own key, capture the password
or the session, and read or swap files in transit, without a trace in the logs. Now the client compares the SHA-256
fingerprint of the presented key with the configured ones and refuses the connection otherwise. There is no warning
period: options without fingerprints fail validation, so the host doesn't start (see [Options](#options)).

Get the fingerprints from a trusted network, or from the server itself:

```bash
ssh-keyscan -p 2222 sftp.example.com 2>/dev/null | ssh-keygen -lf -
# 256 SHA256:nThbg6kXUpJWGl7E1IGOCspRomTxdCARLviKw6E5SY8 [sftp.example.com]:2222 (ED25519)
# on the server: ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

```yaml
Sftp:
  SshServer: sftp.example.com
  SshPort: 2222
  SshLogin: user
  SshPrivateKeyPath: /secrets/id_ed25519
  HostKeyFingerprintsSha256:
    - SHA256:nThbg6kXUpJWGl7E1IGOCspRomTxdCARLviKw6E5SY8   # the "SHA256:" prefix is optional
```

As environment variables: `Sftp__HostKeyFingerprintsSha256__0=SHA256:nThbg6kX…`, `…__1=…` for more.

- **Several key types:** the server offers ed25519, ecdsa and rsa keys and the client picks one; list all fingerprints
  that `ssh-keyscan` prints, or at least the one SSH.NET negotiates.
- **Key rotation:** add the new fingerprint before the server switches keys, remove the old one after.
- **A mismatch** logs `SFTP host key for {Host}:{Port} rejected: SHA256:{Fingerprint}` and throws
  `SftpHostKeyVerificationException` (an `AuthenticationException` with `Host`, `Port`, `PresentedFingerprintSha256`). It
  is not retried, and must not be swallowed: check the server before adding the presented fingerprint.
- **`AllowAnyHostKey: true`** accepts any key and logs a warning with its fingerprint on every connection. Local
  development only; it can't be combined with fingerprints.

The check covers every connection, including the start-up check of `CheckOnStart`.

Checklist:

- [ ] Add `HostKeyFingerprintsSha256` for every SFTP server, taken from a trusted source.
- [ ] Keep `AllowAnyHostKey` out of production configuration.
- [ ] Don't catch and ignore `SftpHostKeyVerificationException`; alert on it.
- [ ] Rotate the SFTP password (or the key) if the server was ever reached over an untrusted network: earlier versions
  didn't verify whom they sent it to.

## Options

`SftpClientOptions` moved to `Microsoft.Extensions.Options`: it no longer implements `IValidatableOptions` and
`ILoggableOptions` of `Curiosus.Configuration`, and `AddSftpServices` no longer takes an options instance: it binds the
options from the `Sftp` section (`SftpClientOptions.SectionName`) itself and validates them when the host starts: single properties by data annotations, the rules across
properties (a password or a private key, the host key) by `SftpClientOptionsValidator`. An invalid configuration throws
`OptionsValidationException` from `IHost.StartAsync` instead of `ConfigurationValidationException` on the first resolve.

Before:

```csharp
var sftpOptions = configuration.GetSection("Sftp").Get<SftpClientOptions>()!;
sftpOptions.AssertValid();

services.AddSftpServices(sftpOptions);
```

After:

```csharp
services.AddSftpServices();                     // binds the "Sftp" section

services.AddSftpServices("Storage:Sftp");       // another section

// code on top of the section; without the section, code-only configuration
services.AddSftpServices(configure: o =>
{
    o.SshServer = "sftp.example.com";
    o.SshLogin = "user";
    o.SshPassword = secrets.SftpPassword;
    o.HostKeyFingerprintsSha256 = ["SHA256:nThbg6kXUpJWGl7E1IGOCspRomTxdCARLviKw6E5SY8"];
});
```

- **Injecting the options:** `SftpClientOptions` is no longer a singleton in DI; take `IOptions<SftpClientOptions>` (or
  `IOptionsMonitor<SftpClientOptions>`). `SftpClientFactory` reads `IOptionsMonitor<SftpClientOptions>.CurrentValue` for
  every new client, so a reloaded configuration (a rotated password or host key) applies to the next client.
- **Your own constructors:** `new SftpClientFactory(options, ...)` takes `IOptionsMonitor<SftpClientOptions>` and
  `new SftpInitializer(...)` takes `IOptions<SftpClientOptions>`; `new SftpClient(options, ...)` still takes the
  options object and doesn't validate it.
- **Validating options yourself** (instead of `Validate()` / `AssertValid()`):

  ```csharp
  var result = new SftpClientOptionsValidator().Validate(null, options);   // rules across properties
  var errors = new List<ValidationResult>();
  Validator.TryValidateObject(options, new ValidationContext(options), errors, validateAllProperties: true);
  ```

- **Subclasses of `SftpClientOptions`** with an overridden `Validate`: the package reads `SftpClientOptions`, so a
  subclass registered in DI isn't used. Move extra settings to your own options class and extra rules to an
  `IValidateOptions<SftpClientOptions>` of your own or to `.Validate(o => ..., "message")` on the builder that
  `AddSftpServices` returns; `SftpClientOptionsValidator` keeps running.
- **`SshPort`** defaults to `22` and must be within 1–65535: the old default `0` passed validation and never connected.
- **`SshPassword`, `SshPrivateKeyPath`, `SshPrivateKeyPassphrase`** are `string?`: nullable warnings may show up where
  you read them.
- **Error paths:** a malformed fingerprint is reported as `HostKeyFingerprintsSha256[1]` (was `HostKeyFingerprintsSha256:1`),
  a missing authentication method as `SshPassword` (was `No auth method`).
- **Printing the options at start:** `ILoggableOptions` is gone; print the section from the configuration instead, for
  example with `services.LogConfigurationOnStart("Sftp")` of `Curiosus.Configuration`.
- **`ITempFileStreamFactory`** is still needed by the client: register it with `AddTempFileServices` of `Curiosus.Tools`.

Checklist:

- [ ] Replace `GetSection("Sftp").Get<SftpClientOptions>()` + `AddSftpServices(options)` with `AddSftpServices()`
  (pass the section path if it isn't `Sftp`, and a `configure` delegate for values set in code).
- [ ] Remove `AssertValid()` / `Validate()` calls on `SftpClientOptions`; catch or log `OptionsValidationException`
  instead of `ConfigurationValidationException`.
- [ ] Inject `IOptions<SftpClientOptions>` where you injected `SftpClientOptions`.
- [ ] Set `SshPort` if your server doesn't listen on 22.
- [ ] Move rules of `SftpClientOptions` subclasses to an `IValidateOptions<SftpClientOptions>`.
