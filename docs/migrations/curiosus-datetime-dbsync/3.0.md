Requires `net9.0` or `net10.0`. Coming from `Curiosity.*` 1.x? Start with the [overview](../index.md).

3.0 rebuilds the package on `System.TimeProvider`: the clock is a `DbSyncTimeProvider` instead of an
`IDateTimeService`, it reads the database through a `DbDataSource` instead of `Curiosus.DAL`, and the first sync no
longer runs as an app initializer. The package doesn't reference `Curiosus.DAL` and `Curiosus.Tools` anymore.

## Breaking changes

- [IDateTimeService → DbSyncTimeProvider](#idatetimeservice--dbsynctimeprovider)
  ([#69](https://github.com/curiosus-dev/Curiosus.Utils/issues/69))
- [Inheritance → composition](#inheritance--composition) ([#69](https://github.com/curiosus-dev/Curiosus.Utils/issues/69))

- [Startup](#startup) ([#69](https://github.com/curiosus-dev/Curiosus.Utils/issues/69))

Removed types: `DbSyncDateTimeService`, `DateTimeServiceInitializer<T>`, `DbDateTimeSynchronizationWatchdog<T>`,
`DbDateTimeOptions`, `AddDbSyncDateTimeServices` and `AddDbSyncDateTimeServices<T>`.

## Registration

2.x read the database time through `ICuriosusDataContextFactory` of `Curiosus.DAL`, which is going away. 3.0 uses the
`DbDataSource` registered in DI, for example by `AddNpgsqlDataSource` of `Npgsql.DependencyInjection`.

Before:

```csharp
services.AddDbSyncDateTimeServices(configuration.DbDateTime);
```

After:

```csharp
services.AddNpgsqlDataSource(connectionString);   // the primary: a replica has its own clock
services.AddCuriosusDbSyncTimeProvider();          // binds the DbTimeSync section
```

The registration binds `DbSyncTimeOptions` from the `DbTimeSync` section (`DbSyncTimeOptions.SectionName`); pass
another path as the first argument, and options set in code as `configure: o => ...`, applied after the section.

`DbSyncTimeProvider` becomes the app-wide `TimeProvider`, replacing the default registration whatever the order:
everything that takes a `TimeProvider` follows the database clock, ASP.NET Core and other libraries (cookie and token
expiry) included. `DbSyncTimeProvider` is registered as itself too, for `IsSynchronized` and `Offset`; code that must
use the local clock regardless takes `TimeProvider.System` directly. A keyed data source is selected with
`dataSourceKey: "..."`.

Checklist:

- [ ] Register the `DbDataSource` of the primary database.
- [ ] Replace `AddDbSyncDateTimeServices(...)` with `AddCuriosusDbSyncTimeProvider()`.
- [ ] Check code that must keep the local clock (rare): it uses `TimeProvider.System` directly.

## IDateTimeService → DbSyncTimeProvider

`IDateTimeService` is replaced by the .NET `TimeProvider`
([Curiosus.Tools 3.0](../curiosus-tools/3.0.md)), which timers, `Task.Delay` and
Polly understand.

Before:

```csharp
public class LeaseService(IDateTimeService dateTimeService)
{
    public bool IsExpired(Lease lease) => lease.LockedUntil < dateTimeService.GetCurrentTimeUtc();
}
```

After:

```csharp
public class LeaseService(TimeProvider clock)   // the database clock once AddCuriosusDbSyncTimeProvider is called
{
    public bool IsExpired(Lease lease) => lease.LockedUntil < clock.GetUtcNow().UtcDateTime;
}
```

`GetUtcNow()` returns a `DateTimeOffset`; `.UtcDateTime` gives the `DateTime` with `Kind = Utc` that
`GetCurrentTimeUtc()` returned. A regex replacement for the calls: `(\w+)\.GetCurrentTimeUtc\(\)` →
`$1.GetUtcNow().UtcDateTime`.

"Now" can jump backwards when a resync lowers the offset. Measure intervals with `GetTimestamp()` and
`GetElapsedTime()`, not by subtracting two `GetUtcNow()` values.

Checklist:

- [ ] Replace `IDateTimeService` injected for the database clock with `TimeProvider`.
- [ ] Replace `GetCurrentTimeUtc()` calls.
- [ ] Check code that measures durations as a difference of two "now" values.

## Inheritance → composition

`DbSyncTimeProvider` is sealed. An app service that derived from `DbSyncDateTimeService` to add its own members (for
example time-zone helpers behind an app interface) takes `TimeProvider` (the database clock) in its constructor instead
and keeps its interface.

Before:

```csharp
public class AppClock : DbSyncDateTimeService, IAppClock
{
    public AppClock(ICuriosusDataContextFactory factory) : base(factory) { }

    public System.DateTime GetMoscowNow() =>
        TimeZoneInfo.ConvertTimeFromUtc(GetCurrentTimeUtc(), MoscowTimeZone);
}

services.AddDbSyncDateTimeServices<AppClock>(options);
```

After:

```csharp
public class AppClock(TimeProvider clock) : IAppClock
{
    public System.DateTime GetMoscowNow() =>
        TimeZoneInfo.ConvertTimeFromUtc(clock.GetUtcNow().UtcDateTime, MoscowTimeZone);
}

services.AddCuriosusDbSyncTimeProvider();
services.AddSingleton<IAppClock, AppClock>();
```

Checklist:

- [ ] Turn subclasses of `DbSyncDateTimeService` into classes that take `TimeProvider`.

## Configuration

The section and its keys changed; periods are `TimeSpan` values.

Before:

```yaml
DbDateTime:
  SyncPeriodMin: 30
```

After (all keys optional, the values below are the defaults):

```yaml
DbTimeSync:
  SyncPeriod: "00:30:00"
  RetryPeriod: "00:00:10"
  InitialSyncTimeout: "00:00:05"
  MaxAcceptedRtt: "00:00:01"
```

Invalid values (zero or negative periods) fail the app start with an `OptionsValidationException`.

Checklist:

- [ ] Move `SyncPeriodMin: N` to `SyncPeriod` as a `TimeSpan` in the `DbTimeSync` section (or the section path passed
  to `AddCuriosusDbSyncTimeProvider`).

## Startup

2.x made the first sync in an app initializer: when it ran before the initializer that created or migrated the
database, the app failed to start. In 3.0 the hosted service `DbTimeSyncService` makes the first attempt when it
starts, waits at most `InitialSyncTimeout` and never fails the start. Until the first successful sync
`DbSyncTimeProvider` returns the local time (`IsSynchronized` is `false`, `Offset` is zero) and the service retries
every `RetryPeriod`. A failed resync keeps the previous offset; a sample whose round trip took longer than
`MaxAcceptedRtt` is discarded. The offset now compensates half of the round trip to the database.

Checklist:

- [ ] Remove initializer ordering written for the sync (the `DateTimeServiceInitializer<T>` registration goes away
  with `AddDbSyncDateTimeServices`).
- [ ] Where a wrong "now" right after the start matters, check `IsSynchronized`.
- [ ] In tests, replace mocks of the data context factory with `new DbSyncTimeProvider(fakeTimeProvider)` or a fake
  `IDbClock`.
