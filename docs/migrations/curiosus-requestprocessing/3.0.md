## Options

`RequestProcessorNodeOptions` validated itself with the options model of `Curiosus.Configuration`
(`IValidatableOptions`, `AssertValid()`), which is deprecated. It is a plain class on `Microsoft.Extensions.Options`
now: the rules are data annotations, and `AddRequestProcessor` binds nothing itself, it returns the
`OptionsBuilder<TOptions>`, which validates the options when the host starts.

| Before | Now |
|---|---|
| `AddRequestProcessor<...>(nodeOptions)` with an instance | `AddRequestProcessor<...>()` returns `OptionsBuilder<TOptions>`; bind with `.BindConfiguration("RequestProcessor")` or configure with `AddRequestProcessor<...>(o => ...)` |
| `nodeOptions.AssertValid()`, an exception on registration or in the bootstrapper constructor | `OptionsValidationException` when the host starts |
| `RequestProcessorNodeOptions : ILoggableOptions, IValidatableOptions`, `Validate(prefix)` virtual | plain class with `[Required]`/`[Range]`; no `Validate` to override |
| `EventsPeriodicCheckSec: 0` allowed | at least 1: 0 made the periodic check loop without a pause |

Workers, dispatchers and bootstrappers still get `TOptions` and `RequestProcessorNodeOptions` from DI: they resolve
the value of `IOptions<TOptions>`, so their constructors don't change.

Before:

```csharp
var configuration = builder.Configuration.Get<AppConfiguration>()!;
configuration.AssertValid();

services.AddRequestProcessor<
    MyRequest, MyWorker, WorkerBasicExtraParams, MyBootstrapper, MyNodeOptions, MyDispatcher, MyProcessingInfo>(
    configuration.RequestProcessor);
```

After:

```csharp
services
    .AddRequestProcessor<
        MyRequest, MyWorker, WorkerBasicExtraParams, MyBootstrapper, MyNodeOptions, MyDispatcher, MyProcessingInfo>()
    .BindConfiguration("RequestProcessor");
```

### Subclasses of the options

Keep the subclass: everything `AddRequestProcessor` registers works with it. Move its rules out of the
`Validate(prefix)` override:

- single-property rules become attributes on its properties (`[Required]`, `[Range]`, `[Url]`, ...); the attributes of
  `RequestProcessorNodeOptions` keep working on the subclass;
- nested options get `[ValidateObjectMembers]` (a collection of them `[ValidateEnumeratedItems]`), so their attributes
  are validated too;
- rules over several properties go to your own public `IValidateOptions<MyNodeOptions>`, registered next to the
  processor. The validation of the base options runs anyway, the validator checks only your rules.

Before:

```csharp
public class MyNodeOptions : RequestProcessorNodeOptions
{
    public int BatchSize { get; set; } = 10;

    public StorageOptions Storage { get; } = new();

    public override IReadOnlyCollection<ConfigurationValidationError> Validate(string? prefix = null)
    {
        var errors = new ConfigurationValidationErrorCollection(prefix);
        errors.AddErrors(base.Validate(prefix));
        errors.AddErrorIf(BatchSize < 1, nameof(BatchSize), "can't be less than 1");
        errors.AddErrorIf(BatchSize > WorkersCount * 10, nameof(BatchSize), "too big for the workers");
        errors.AddErrors(Storage.Validate(nameof(Storage)));
        return errors;
    }
}
```

After:

```csharp
public class MyNodeOptions : RequestProcessorNodeOptions
{
    [Range(1, int.MaxValue)]
    public int BatchSize { get; set; } = 10;

    [Required]
    [ValidateObjectMembers]
    public StorageOptions Storage { get; set; } = new();
}

public class MyNodeOptionsValidator : IValidateOptions<MyNodeOptions>
{
    public ValidateOptionsResult Validate(string? name, MyNodeOptions options)
    {
        var builder = new ValidateOptionsResultBuilder();
        if (options.BatchSize > options.WorkersCount * 10)
            builder.AddError("too big for the workers", nameof(options.BatchSize));

        return builder.Build();
    }
}

services
    .AddRequestProcessor<
        MyRequest, MyWorker, WorkerBasicExtraParams, MyBootstrapper, MyNodeOptions, MyDispatcher, MyProcessingInfo>()
    .BindConfiguration("RequestProcessor");
services.TryAddEnumerable(ServiceDescriptor.Singleton<IValidateOptions<MyNodeOptions>, MyNodeOptionsValidator>());
```

A subclass of a subclass works the same way for attributes: each level puts them on its own properties. Validators
are different: only the `IValidateOptions<T>` of the type you register (`TOptions`) runs, an
`IValidateOptions<MyNodeOptions>` is not called for `MyDerivedNodeOptions`. The validator of the derived class calls
the one of its parent and adds its result:

```csharp
public class MyDerivedNodeOptionsValidator : IValidateOptions<MyDerivedNodeOptions>
{
    private readonly MyNodeOptionsValidator _parent = new();

    public ValidateOptionsResult Validate(string? name, MyDerivedNodeOptions options)
    {
        var builder = new ValidateOptionsResultBuilder();
        builder.AddResult(_parent.Validate(name, options));
        // rules of MyDerivedNodeOptions
        return builder.Build();
    }
}
```

Checklist:

- [ ] Replace `AddRequestProcessor<...>(instance)` with `AddRequestProcessor<...>().BindConfiguration("...")` (or a
  `configure` delegate) and remove `AssertValid()` calls for these options.
- [ ] Move the `Validate(prefix)` override of your options subclass to attributes and an `IValidateOptions<T>`; drop
  `IValidatableOptions` and `ILoggableOptions`.
- [ ] Make get-only nested options settable (`{ get; set; } = new();`) and mark them `[ValidateObjectMembers]`.
- [ ] Set `EventsPeriodicCheckSec` to 1 or more if it was 0.
